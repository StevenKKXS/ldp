# Agent 启动文档: PTP Encoder 改进双方向实验管理

Date: 2026-05-18

## 0. 启动目的

当前项目围绕 PTP / Diffusion Policy 的 encoder 改进同时推进两个候选方向。两个方向都还没有最终确认有效，需要由 agent 先保存文档、review 可行性、提出异议，然后按顺序进行实验验证。

agent 的核心职责不是直接假设某个方向有效，而是:

```text
保存已有 plan -> review 是否有问题 -> 提出异议或补充建议 -> 确认没有新 idea 后按顺序实验 -> 记录状态和关键 observation
```

为了避免后续询问进度时出现幻觉，agent 必须维护清晰的文档入口、当前采用的 plan、每个方向推进到哪里、每次实验的真实结果和未完成事项。

## 1. 当前已有两个方向

### Direction A

```text
Future-Action / Behavior Contrastive History Encoder
```

核心想法:

```text
用未来专家动作相似性组织 history embedding，使 encoder 学到 action-aware / behavior-aware 的历史表征。
```

文档路径:

```text
docs/direction_a_future_action_contrastive/plan_init_2026-05-18.md
```

该文件应记录方向目标、核心假设、输入形式、contrastive loss 设计、hard negative 设计、接入 PTP 的方式、Square / ToolHang 优先实验矩阵、Push-T / Transport 扩展条件、ablation 设置和实验 observation log。

### Direction B

```text
Action-Sequence Predictive Encoder Pretraining
```

核心想法:

```text
把“图像/历史到动作序列翻译”弱化为 encoder pretraining，让 encoder 通过预测 past + future action sequence 学到 action-predictive belief representation。
```

文档路径:

```text
docs/direction_b_action_sequence_predictive/plan_init_2026-05-18.md
```

该文件应记录方向目标、核心假设、输入形式、action prediction decoder 设计、future-only 与 past+future prediction 对比、loss 设计、接入 PTP 的方式、Square / ToolHang 优先实验矩阵、Push-T / Transport 扩展条件、ablation 设置和实验 observation log。

## 2. docs 目录结构

```text
docs/
  main.md
  agents.md
  status.md
  plans/
    plan_init_2026-05-18.md
  direction_a_future_action_contrastive/
    plan_init_2026-05-18.md
    obs_log.md
    experiments.md
    status.md
  direction_b_action_sequence_predictive/
    plan_init_2026-05-18.md
    obs_log.md
    experiments.md
    status.md
```

`docs/main.md` 是总入口，说明当前采用哪个 plan、两个方向分别在哪个文件夹、每个文件记录什么。

`docs/agents.md` 是 agent 工作规范入口，记录 agent 应该如何 review、如何实验、如何更新状态、如何避免幻觉。

`docs/status.md` 是全局状态表，记录两个方向当前分别推进到哪一步。

后续如果有重大修改，不直接覆盖旧 plan，应创建新文件，例如:

```text
plan_update_2026-05-xx.md
plan_ablation_update_2026-05-xx.md
plan_failed_direction_revision_2026-05-xx.md
```

并在入口文件中更新当前采用的 plan。

## 3. 实验推进规则

第一阶段只验证:

```text
Square
ToolHang
```

每个方向至少需要:

```text
PTP baseline
same architecture no-pretrain baseline
ours frozen
ours finetune
```

第二阶段只有在第一阶段出现以下情况时才扩展:

```text
ours > same architecture no-pretrain baseline
```

或者:

```text
ours 在至少一个任务上明显提升 PTP baseline
```

扩展任务:

```text
Push-T
Transport
```

## 4. 不要过早合并两个方向

Direction A 和 Direction B 的组合版本:

```text
L = L_contrast + lambda * L_pred
```

只有在两个方向分别完成单独验证后再考虑。

## 5. Agent review 重点检查

agent 在执行前应 review:

1. 两个方向是否都能挂到当前 PTP 代码中。
2. encoder 输出维度如何接入 diffusion condition。
3. 是否已有 PTP baseline checkpoint。
4. Square / ToolHang 的数据加载和 evaluation 是否正常。
5. 是否能复现实验表中的已有 PTP 分数。
6. 是否有必要先跑 same-architecture no-pretrain baseline。
7. Direction A 的 action distance 是否需要 normalization。
8. Direction B 的 action prediction decoder 是否过强。
9. frozen / finetune 是否都能在代码中明确控制。
10. 每个实验是否有独立 experiment id 和日志路径。

如果 agent 对 plan 有异议，应先写入对应方向的 `obs_log.md` 或 `status.md`，并在执行前反馈。

## 7. 后续更新规则

如果之后讨论产生新 idea 或实验设计变化:

1. 不直接覆盖旧 plan。
2. 在对应目录创建新的 plan 文件。
3. 在 `docs/main.md` 中更新 active plan。
4. 在 `docs/status.md` 中记录切换原因。
5. 在对应方向 `obs_log.md` 中记录产生新 plan 的 observation。

命名示例:

```text
plan_update_2026-05-20.md
plan_hard_negative_revision_2026-05-22.md
plan_predictive_decoder_revision_2026-05-23.md
```

## 8. 第一条执行指令

agent 启动后先:

1. 创建 docs 目录结构。
2. 保存 `docs/plans/plan_init_2026-05-18.md`。
3. 保存 Direction A 初始 plan。
4. 保存 Direction B 初始 plan。
5. 创建 `docs/main.md`、`docs/agents.md`、`docs/status.md`。
6. 为两个方向分别创建 `status.md`、`experiments.md`、`obs_log.md`。
7. 阅读并 review 两个方向的 plan。
8. 如果有异议，先记录并反馈。
9. 如果没有新关键 idea，按 Square / ToolHang 顺序开始最小实验。
10. 每次实验后更新 status、experiments 和 obs_log。
